## Completeness

We first evaluated the depth and complexity of the main epics in your app, along with their contribution to the app, the tangible value they provide to the user, and their alignment with the app’s goals.

We evaluated the extent to which your app meets the course requirements articulated at the start of the semester, and whether they are implemented effectively, they integrate seamlessly, and are indeed essential to the app.

We also looked at the robustness and completeness of the different features you implemented: are all the features finished and polished, are they secure and bug-free, and are they thoughtfully designed.

The application implements two main EPICs. The first one allows users to browse posts and interact with other users in order to exchange services, either through skills or cash. The second EPIC focuses on offering services directly by creating posts. Overall, these EPICs are implemented end to end: users can create an account, complete onboarding, edit their profile, browse the feed, and publish posts.

However, several features that are typically expected for this type of application are currently missing. For instance, once an offer is accepted, it is no longer possible to view its details, as accepting an offer only opens a chat with the other user. This makes it impossible to revisit the original offer. Similarly, users cannot view another user’s profile to see all the offers they have published.

The filtering system is also quite limited. Users can only filter by distance, with a maximum of 20 km and no option to select a specific area. Filtering by skill is not available either, even though the application includes a star rating system per skill, which cannot be used as a filter in the feed.

Profile customization options are minimal. Users can only set a profile name and a profile picture. Allowing additional elements such as a description, multiple images, or videos would help users better understand the person they are considering exchanging skills with.

The chat system also has usability issues. When interacting with multiple offers from the same user, separate chats are created, but it is not clear which chat corresponds to which offer.

On the technical side, the project makes meaningful use of at least one public cloud service, integrating it in a way that contributes to the core functionality of the application. The authentication mechanism works reliably and aligns with the expectations for this milestone. A phone sensor is integrated in a way that adds real value to the user experience and supports the purpose of the app. Finally, the application demonstrates an average but functional approach to offline mode and data synchronization, handling transitions between offline and online states smoothly and without data loss.

For this part, you received 4.3/6.

## Functionality

In this context, we assessed your app's ability to handle unexpected inputs provided by clueless or malicious users (including spamming buttons, entering wrong inputs, stopping a process mid-way, etc.); we wanted to see that your app handles all edge cases gracefully, has comprehensive error handling, and includes robust mechanisms for maintaining stability under stress.

We then evaluated the performance and reliability of the final product, i.e., the APK: we wanted to see that your APK is stable and the UI responds quickly and has seamless navigation.

Next we looked into your implementation of user authentication and multi-user support: does the app correctly manage users, can users personalize their accounts, does the app support session persistence, are multi-user interactions well supported, can accounts be used on another device, and is account information preserved when switching devices.

There are several issues with the end-to-end core flow of the application. First, it is not possible to create an account using Google: the flow automatically redirects users to the standard onboarding process using only email, which makes the Google sign-up option effectively unusable. The onboarding experience itself is fairly good, and the explanatory message for the writing step is appreciated, even if the visual presentation could be improved.

The main problems are concentrated around the chat feature. The behavior when switching between “pending,” “reply,” and ongoing conversations is confusing: conversations appear and disappear, and the overall flow between these states feels buggy and unclear. This significantly impacts usability.

There are also issues with post creation. When required tags are not completed, the error messages are difficult for users to understand. Additionally, image handling is poorly managed: very large photos can be uploaded, and creating a post with heavy images can take an excessively long time, sometimes several minutes, which severely degrades the user experience.

The notification system also appears to be buggy. When accepting offers, multiple notifications (three or four) are sometimes sent for a single action. This seems to be caused by rapidly clicking the accept button, which triggers multiple notifications to the other user.

Overall, the development shows many oversights regarding real-world user behavior, as opposed to ideal usage scenarios. In realistic conditions, several flows either malfunction or behave unpredictably. The positive aspect is that there are no critical application crashes: the issues are mostly related to usability rather than stability, and the codebase itself appears stable.

In terms of data persistency, the application performs well. Data is correctly saved and remains available after logging out and back in. Synchronization in the messaging system also works reasonably well, with only minor delays. However, robustness against unexpected or irregular user input is weak, particularly in the chat, where some elements reappear in strange ways.

From a functional standpoint, account creation and login work as expected, users can reconnect, and the core collaboration feature—communicating through chat, is operational. That said, the overall feature depth and complexity of the application are quite limited. The app provides only the bare minimum: users can browse posts and exchange messages, but many features typically expected for this type of application are missing.

In terms of feature complexity, the application remains shallow. The two most complex features appear to be the chat system, which is currently quite buggy, and the distance filter, which works but is restricted to a very small radius.

For this part, you received 3.9/6.

## User Experience

For this part, we wanted to see how intuitive and user-friendly the app is for real users. Beyond having good usability, did you pay attention to streamlining the interactions, is it easy to figure out, can new users start making good use of the app quickly, are the interaction flows well thought out and refined.

Navigation and overall architecture are generally good, and the login and account creation flows work very well. However, some parts of the navigation are unclear or inefficient, particularly within the Profile Information section, where settings, posts, and skills are mixed together. There are no dedicated pages for managing posts or settings, which makes the structure confusing.

The bottom navigation bar is also inconsistent, as it includes an action to add a post rather than only navigation between pages. The feed is visually appealing, but its card-based design suggests swipe interactions that are not supported, which can be misleading. In addition, there is no way to undo actions, such as accidentally rejecting an offer.

Filtering options are very limited, and the “Use Live Location” button is unclear. In the chat section, while notifications work reasonably well in terms of UI, the distinction between “pending,” “replies,” and “ongoing” conversations is not clearly explained.

Visually, the application is consistent overall, with well-functioning light and dark themes, despite some minor spacing issues, especially in the chat. Onboarding and guidance are average: aside from login and a brief explanation of skills, users receive little help, making the app hard to understand without external documentation.

Finally, in terms of feature value and originality, the application is quite weak. It lacks many small but important features expected for this type of app, which makes the overall user experience more complex than necessary, despite a simple core concept.

For this part, you received 3.8/6.

## Design and Maintainability

We evaluated whether your code is of high quality and employs best practices.
We expect the codebase to be polished, well documented, follow consistent conventions, be modular, and allow for easy modifications.
You should be able to employ advanced techniques by now, such as asynchronous functions (flows, coroutines), good resource management, and automated dependency injection (e.g., with Hilt).

We also assessed your overall app architecture and design, looking in particular at aspects surrounding robustness and scalability.
We looked at both the codebase and the documentation of the app (Wiki and architecture diagram), we expect your design to demonstrate thoughtful consideration for performance, maintainability, and future growth.

Your codebase is well structured and scalable, with packages clearly organized by responsibility, which makes it very easy to navigate. An inconsistency was noted in the unit tests, where the viewmodel package contains just a single test, which doesn’t align with how the other ViewModel tests are organized.

Naming is generally clear and readability is good; however, some details have not been given enough attention. For example, the ChatScreen still contains a commented-out preview block, and large commented-out sections in production files are considered poor practice and should be removed. In addition, some artifacts from the template, such as SecondActivity.kt, were left in the codebase and should have been cleaned up.

The MVVM pattern is applied well throughout the project, which is great. 

There are no high-severity issues, which is excellent. However, there are still several medium-severity ones, especially functions with too many parameters and some commented-out code that was left behind. Cleaning these up would improve overall code quality.

For this part, you received 5/6.
